# First-case diagnostic admission (experimental version1)

This operator-only route runs one real **schema2 subject** on an explicitly
unqualified platform while retaining its failed qualification hold. It does not
qualify/release tools, accept a mod, switch the global host, or authorize work.
Normal qualification-release, platform binding and ordinary next stay strict.

Version1 is deliberately bound to the independently reviewed29October2026 Q1
(`autotest-se-finite-native-20261029-1`), original published CLAW0.6.2 archive,
baseline audit, installation plan, seven-path resume slot and independent
race/staging review. Source constants bind their exact reviewed hashes. A new
qualification/case or second diagnostic requires a separately reviewed extension;
changing a cycle id cannot refresh the allowance.

The narrow task accounting is **two starts total: known Q1=1 plus at most one
diagnostic**. This is a subset of the owner's unchanged outer six-start window,
not six additional starts. Historical cumulative accounting remains null. Current
cycle authority, cancellation/resume lineage and original deadline must still be
independently verified. A hash or this document authenticates no human instruction.

## Required sequence

Use the same host root/SQLite queue and a frozen reviewed Dashboard/executor.
These commands change durable state; this document does not ask an operator to
execute them automatically.

1. `diagnostic-prepare PREPARATION.json` grants only the exact oldest ELIGIBLE
   waiting cycle ticket under the unchanged sole Q1 hold. Inactive/expired waiting
   entries are terminalized with retained audit history; another active earlier
   ticket, reserved/blocked owner or unknown hold blocks. It performs no install
   or launch. Repeat identical preparation returns the same reservation.
2. The exact origin reads slots and uses ordinary file-backed `slot-ack`. It may
   now perform only the reviewed native MO2 archive installation and declared
   manager side effects under the existing native mutex/owner protocol. Native
   source accounting must be verified after refresh. Do not run the previous
   install helper unchanged if it rejects every hold: it needs the explicitly
   reviewed diagnostic reservation, not a blanket hold exception.
3. The origin submits the ordinary actual installed schema2 order. The earlier
   prospective draft is evidence of intended content, not an installed-input
   claim. The final order/specification and all installed inputs must match.
4. `diagnostic-freeze FREEZE.json` independently checks installation settlement,
   every current input/VFS winner, provider/code closure, semantic compilation
   and each native method. It freezes an explicitly unqualified platform attempt.
5. `diagnostic-execute EXECUTION.json` atomically consumes that exact identity
   under native mutex+SQLite transaction and claims only that subject. It leaves
   Q1's hold intact and invokes the ordinary parent/fresh-child executor pipeline.
6. After factual execution/cleanup/collection, ordinary report-ready/outbox return
   raw checks only to the exact origin. `diagnostic-complete COMPLETION.json`
   separately reviews the ended packet/worker/archive and records actual1start.
   It clears no hold and admits no second diagnostic. An uncertain/lost-response
   attempt stays consumed/held with unknown accounting; absence of a run is not0.

One optional field is `releasedWorkDeferral:{path,sha256}`. It is NOT a global
defer API or job lifecycle. It applies only to the exact untouched released
Morphbench static-capsules order reviewed for this first case. Without the
review, valid pending released work blocks preparation even under the Q1 hold.
The pinned `one-shot-unavailable-preparation-deferral` review binds diagnosticId,
approved subject specification, same current owner/deadline, priority evidence,
Q1 executor inventory hash and the independently anchored availability review.
The source rechecks exact queue/request/release/owner/event facts, absence of
preparation/attempt/file traces, and the same frozen pure platform validator's
exact fourteen unsupported shapes out of fifteen. Import/I/O/runtime errors or
now-supported methods are not unsupported-capability proof. Any other ready
release still blocks. The Morphbench order, release, history, queued status,
files and counts remain unchanged; no packet, failure or notification is created.
The deferral pin/audit belongs only to this immutable diagnostic preparation and
grants no later admission, renewed deadline or extra start.

`installation` must equal the ten original archive members/destinations in the
anchored plan. Original archive/sidecar and baseline audit remain pinned. The
anchored slot has seven write paths while the old plan has six; both remain
immutable. Broad profile/log paths declare native UI side effects; they are
**never provider exemptions**. `protectedInputs` is the complete Q1 input closure
except the exact source-profile modlist and ModOrganizer.ini. All1149 original
subject/dependency bytes remain included; plugin/load-order/config files stay
protected. Before grant, the original modlist must still match its Q1 pin.

Task accounting is an object with kind=`diagnostic-task-start-accounting`,
cycleId,qualificationId,cumulativeActualGameStarts=null,actualGameStartsBefore=1,
maximumActualGameStarts=2,verifiedBy,reason. A cleared/recreated Q1 hold, changed
hold note, later qualification/ordinary/native admission or another diagnostic
identity refuses. The executor path AND complete inventory must equal Q1 before
any candidate code is imported. No caller-selected replacement inherits Q1 proof.

The known-fault review contains kind=`known-external-shutdown-fault`,
qualificationId,phase=`ordinary-shutdown`,module:{path,sha256},dump,wer,debuggerLog
(each a pin), nonempty evidence pins,verifiedBy,reason. The verifier independently
checks the actual fixed B6 hash, bounded MDMP PID/creation/module/RVA/timestamp/
CodeView-age, WER full FILETIME birth/path, and pinned private-symbol teardown
stack. Every declared Q1 action plus the unique same-run bootstrap must pass;
other faults/reasons/collection errors or a forced/mid-test exit refuse. This is
not an AV whitelist and does not excuse another future failure.

`diagnostic-show ID` supplies read-only current Dashboard reservation proof for
the origin's native installer. It rechecks exact authority/hold/slot/source pins,
but deliberately reports nativeIdleVerified=false and launchGranted=false. The
holder must still independently own the native mutex and verify actual MO2/game
state. An identical repeated preparation returns retained status and explicitly
grants no new installation, including after the modlist legitimately changes.

## Freeze and native installation receipt

FREEZE.json exact fields: schemaVersion1,kind=`one-shot-diagnostic-freeze`,id,
subjectOrderSha256,platform:{path,sha256},methodReview:{path,sha256},
installationReceipt:{path,sha256},verifiedBy,reason.

The platform has exactly schemaVersion1,kind=`one-shot-diagnostic-platform`,
qualified=false,interface=`polygon-actions/1`,config,inputs,operations. Provider
inputs must come from the complete protected Q1 closure. Global configuration is
not changed. The ordinary compiler and selected executor validators are reused.

Receipt fields checked include kind=`diagnostic-native-installation-receipt`,
preparationId,slotId,orderId,sourceThreadId,installationPlan,baselineAudit,
archiveInstalled=true,managerRefreshed=true,installationSettled=true,profile,
installedInputs (exact final order.inputs),vfsWinners (all ten exact target/SHA
rows),nonempty pinned raw evidence,verifiedBy,reason. Operator review must verify
the native manager/API evidence and actual Installed accounting; self-asserted
booleans are not a substitute. Only the new published base may be added at the
highest priority: all prior mod states/order remain. The new mod directory must
contain exactly the ten archive files plus native meta.ini, with no extra DLL.

The method review has exactly schemaVersion1,kind=`diagnostic-method-review`,
qualificationPacket,steps,evidence,verifiedBy,reason. One steps row per compiled
step: name,compiledStepSha256,methodStatus,nativeMethodCovered=true,reason.
methodStatus is `observed-Q1` only for matching actual Q1 arguments, otherwise
`reviewed-diagnostic-target`. Backend/operation/domain/action must have positive
Q1 evidence; unsupported native methods refuse. A business branch under test is
not preclaimed successful. The source/offline pure compareSnapshot branch must
remain explicitly disclosed as such. These observations qualify no rendered mesh.

loader defaults. A raw-vs-effective comparison would incorrectly refuse unchanged
configuration. Parse a captured hash-checked config snapshot, then recheck original
pins before freezing; never adopt a different file hash after parsing.

Only a new isolated runtime and the explicit SUT-target append are permitted:

its permission or a permission without that target refuses before game start.
Q1's human race method evidence does not prove the werewolf business result.

## Execution, recovery and completion

EXECUTION.json exact fields: schemaVersion1,kind=`one-shot-diagnostic-execution`,
id,platformPlanSha256,verifiedBy,reason. Parent and child recheck source, inputs,
authority and ownership. The selected child rejects mixed executor caches, records
its exact native worker and allows one launch request/no scenario restarts. The
parent is bounded by900seconds or the earlier current deadline; timeout stops only
that exact child and leaves recovery to the owned guardian. Common startup and
verified loaded gameplay readiness precede factual subject actions.

COMPLETION.json exact fields: schemaVersion1,kind=`one-shot-diagnostic-completion`,
orderId,packet:{path,sha256},verifiedBy,reason. It requires actual1native start,
ended exact worker/owned identities, complete ordinary packet and restored/archived/
removed profile. It cannot infer0 or change results. Repeating consumed execution
cannot launch; an altered review refuses. A new id/cycle is not another allowance.

Normal test projection is unchanged. A shutdown-failed execution can keep an
incomplete/interrupted test outcome despite passed subject checks. Return the
actual per-check evidence and technical failure; do not invent tested_successfully,
global qualification or release acceptance. The first20critical checks are a
milestone, not completion of CLAW's larger release/testing goal.
