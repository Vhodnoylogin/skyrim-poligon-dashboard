# First manual client in an existing native session

`qualification-admit-manual-client ID REVIEW.json` admits only the original pinned
owner-controlled manual scene after the exact terminal owned-INI pre-client
refusal. It never calls a game runner, installs files, changes INI/profile data,
replaces a worker, clears a hold or renews an original deadline.

The independent operator reviews current manual authority, exact original plan
and failed dispatch, worker/game/state identities, original deadlines, zero prior
client/claim/actions/fixtures and the complete new implementation pins. Review
kind is `qualification-first-manual-client-admission`; flags are
`manualOnlyReviewed`, `sameOwnedSessionReviewed`, `noPriorClientReviewed`,
`originalDeadlineReviewed`, `currentOwnerAuthorityReviewed`, `originalPinsReviewed`.
All must be factual true. Templates are not approval. Original qualification
authority and every pin are rechecked through the strict owned-MO2 witness.

The corrected byte matcher replaces only `selected_profile` value bytes and
preserves each original terminator/BOM/other byte. It does not normalize the file
or permit any other change. Current process, Bridge, copy and backup guards stay
mandatory. The original interactive phase event fixes the native deadline.

The existing original worker/guardian continue owning the game. One additive
`first-manual-client/` directory and durable intent precede one original-client
CreateProcess. The original exclusive run claim remains mandatory. Any prior
intent, claim, action or additive directory refuses repetition, including an
uncertain failed attempt. Only the retained data-client handle is supervised;
its original client window is clamped to the existing native/outer deadlines.
Expiry is checked again immediately before spawn. No finish/game-close command
is injected by this admission helper.

The original error-bearing dispatch remains unchanged and may still be written
by its original worker. The additive client owns its own report/manifest/dispatch
under `first-manual-client/subject-companion/`. Qualification collection validates
the admission, original refusal and retained new implementation bytes before
selecting that separate evidence context. All existing delivery/assertion/
identity/exit/restoration checks still apply. Recording this binding adds zero
physical game starts and grants no mod/provider acceptance or automatic retry.
